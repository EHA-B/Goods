Behavior after this fix:
1. Saving a salary/wage expense through the worker flow creates, atomically:
   - worker_payments row
   - one cashbox_transactions row
   - one transactions row (expense)
   - worker balance update
   - cashbox balance update
2. The cashbox is deducted exactly once.
3. worker_payments.transaction_id links the worker payment to transactions.id.
4. Reversing a worker payment restores cashbox + worker balance and marks the linked financial transaction cancelled without a second cashbox reversal.
5. Cancelling the linked financial transaction from the financial-transactions UI delegates to worker payment reversal, so both entry points remain consistent.
6. Worker details show a button to open the linked financial transaction.
